## Instructions for maintaining this file

1. Read this file at the start of each new work session, with current instructions and the latest handover. Read the action tracker if one exists.
2. Verify important facts against the live repository; this file can become outdated.
3. Update it after meaningful changes to scope, decisions, architecture, verified work, research, risks, lessons, preferences, or next steps.
4. Keep one authoritative home for each fact. Link to detailed records instead of repeating them here.
5. Clearly distinguish verified facts, user decisions, assumptions, experiments, and recommendations.
6. If information is missing, mark it unknown or ask only when it blocks safe progress.
7. If write access is unavailable, prepare the exact update and say that it remains unsaved. Never claim it was saved until the change is committed and verified.

**Template-repository exception:** the Collaborative Development Template itself is not a project using the template. Do not create `docs/PROJECT_MEMORY.md` in the template repository; use its private maintainer records instead.
