## Maintenance rules for the AI
1. Read this file at the start of every new work session, alongside current project instructions and the latest handover. Verify critical facts against the live repository; memory can become stale.
2. Update it whenever durable context changes: vision, scope, confirmed decisions, architecture, verified implementation, research, risks, lessons, relevant preferences, milestone status, or next actions.
3. Reconcile it before substantial handovers and after meaningful milestones. Do not wait until project completion.
4. Keep it concise. Update sections in place, remove stale or contradicted facts, and link to detailed logs instead of duplicating them.
5. Distinguish confirmed facts, user decisions, assumptions, experiments, and recommendations. Include dates and source references where useful.
6. Never invent missing context. Mark it unknown or ask only when it materially blocks progress.
7. Never store secrets, credentials, sensitive personal data, confidential third-party information, or raw private-chat transcripts. A private repository is not a secret store.
8. Store only the minimum durable, project-relevant context needed for continuity.
9. Keep this memory synchronized with specialist records; each fact should have one authoritative home.
10. If GitHub write access is unavailable, prepare the exact update and clearly state that it remains unsaved. Never claim persistence until the file change is committed and verified.
